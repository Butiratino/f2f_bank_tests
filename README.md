# F2F Bank tests

Playwright-тесты для приложения F2F Bank. Приложение запускается через Docker, тесты находятся в каталоге `tests/`.

## Запуск приложения

```bash
docker compose up -d --build

```

После запуска приложение доступно по адресу `http://localhost`.

## Запуск тестов

```bash
cd tests
npm install
npx playwright install chromium
npm test

```

Дополнительные команды:

```bash
npm run typecheck
npm run test:api
npm run test:profile
npm run test:transfer
npm run test:balance
npm run test:transaction
npm run test:ui-suite
npm run test:regression
npm run test:smoke
npm run test:need2fix
npm run report

```

Теги позволяют запускать отдельные группы сценариев.

В suite есть UI-тесты и отдельные API-тесты. API используется также для подготовки уникальных пользователей и начального состояния, когда это не является частью проверяемого UI-сценария.

## Структура проекта

* `tests/tests/` - сценарии UI и API;
* `tests/pages/` - page objects;
* `tests/helpers/` - общие действия и тестовые данные;
* `tests/NOTES.md` - краткие заметки и известные проблемы приложения.

Тесты с `@need2fix` проверяют дефекты приложения, которые пока воспроизводятся.

## Тестовые сьюты и покрытие

Тесты разделены на домены (через теги и файлы), покрывающие основные бизнес-процессы приложения как на уровне UI, так и напрямую через API:

* **Авторизация (`@auth`)**: Сценарии входа в систему. Проверяется генерация сессии при валидных данных, отказы при неверных учетных данных, защита приватных роутов без авторизации, а также полное уничтожение сессии (логаут) и недопустимость доступа по старой cookie.
* **Регистрация (`@registration`)**: Процесс создания нового пользователя. Покрывает успешный сценарий (Happy Path), блокировку дубликатов email, а также обширную валидацию полей (формат email, сложность пароля, наличие обязательных данных).
* **Баланс и пополнение (`@balance`)**: Финансовые операции пользователя. Включает тесты на пополнение счета, проверку обновления баланса на фронтенде и фиксацию транзакций с типом `deposit` в истории. Проверяются граничные значения допустимых сумм (копейки, целые числа, ограничения на формат).
* **Переводы (`@transfer`)**: Ключевой флоу движения средств. Проверяется списание денег на указанный телефон, запись операции с типом `withdrawal`, отказ в переводе при недостаточном балансе, а также жесткая валидация номера телефона и назначения платежа.
* **Профиль (`@profile`)**: Базовые проверки интерфейса на корректное отображение сохраненных персональных данных (имя, фамилия, email) для авторизованного пользователя.

## Приоритеты тестов (Критичность)

Для обеспечения прозрачности покрытия используется строгая градация тегов приоритетности, основанная на рисках для бизнеса:

* **`@critical` (Критический):** Основной пользовательский путь (Happy Paths): успешная регистрация, авторизация, пополнение баланса и выполнение перевода. Сюда же отнесены критичные уязвимости: изоляция сессий, доступ к приватным данным без токена, подмена ролей (создание admin) и полная потеря данных (несохранение деталей перевода).
* **`@high` (Высокий):** Основные негативные сценарии (ошибка входа, недостаток средств для перевода) и строгая бизнес-валидация (наличие обязательных полей, соблюдение формата email, денежного стандарта до двух знаков и валидность телефона). Также включает отлов серверных ошибок (возврат 500 вместо 422).
* **`@medium` (Средний):** Граничные проверки (максимальные лимиты длины текстовых полей), специфичная валидация (ввод только пробелов, кириллицы, спецсимволов), ошибки управления состоянием UI (необновляющийся баланс после релогина) и утечка фоновых неавторизованных запросов.
* **`@low` (Низкий):** Второстепенная UI/UX логика: открытие и закрытие модальных окон без действий, статичное отображение read-only данных, переходы по ссылкам и визуальные дефекты верстки.
